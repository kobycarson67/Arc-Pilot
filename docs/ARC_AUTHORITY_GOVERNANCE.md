# ARC AUTHORITY GOVERNANCE — ANTI-LOSS RULES

## Why this exists
ARC lost active conversational continuity even though the product had been designed in depth. This file prevents a future conversation, Codex task, schema migration or parity program from silently narrowing the product.

## Required hierarchy
1. Institutional/external source authority (official Standards, FERPA, school rubrics/forms).
2. Explicit instructor product/design decisions and confirmations.
3. Current accepted ARC product authority (`ARC_MASTER_PRODUCT_AUTHORITY.md`).
4. Classroom Readiness Contract for launch scope.
5. Domain design/milestone authority.
6. Current code/tests/physical verification evidence.
7. Roadmap concepts.
8. Historical/superseded ideas retained for lineage.

A lower level must not silently override a higher level.

## Required pre-task check
Before substantial ARC work:
- verify repository commit/tree/working tree;
- read Master Product Authority;
- read Classroom Readiness Contract if launch-related;
- identify affected domain authority and source material;
- state whether work is parity, completion, source reconciliation, roadmap, or production cutover;
- create/verify rollback reference where repository changes are authorized.

## No silent policy invention
If exact authority is absent, mark `UNRESOLVED` and stop at the policy boundary. Examples: Today's Focus ranking, complete Notifications triggers, exact Administration report catalog, Resource model, Safety escalation thresholds.

## No silent product narrowing
The 47-row parity contract protects existing production workflows; it does not define the whole ARC vision. Roadmap and Classroom Ready scope are separately authoritative.

## No silent acceptance
A schema/store/service can be service-ready while UI/content remains unaccepted. Existing Lesson content can be preserved without being instructionally approved. A source example can guide output without becoming district policy.

## Supersession
When a decision changes, preserve the old decision and explicitly mark the new controlling authority. Example: Level 4=Proficient is superseded by Level 3=Proficient / Level 4=Advanced.

## Derived-view rule
Dashboard, Forecast, Fast Roster, Open Shop recommendations, Notifications, Grade Ready and similar views should derive from owning records rather than persist competing truth unless a separately approved authority explicitly requires persistence.

## Teacher-judgment rule
Recommendations, AI feedback, booth suggestions and planning aids inform professional decisions. They do not silently replace instructor judgment.

## Continuity update rule
Every major completed stage must update durable continuity with:
- what changed;
- what did not change;
- authority state;
- rollback;
- tests/physical verification;
- newly settled decisions;
- unresolved decisions;
- exact next bounded step.

## Source preservation
Recovered photos/PDFs/forms/maps/rubrics/examples remain byte-preserved in source authority with hashes/provenance. Transcriptions do not replace originals.

## Classroom Ready convergence
New work should answer: **Which unchecked Classroom Readiness requirement does this close?** If none, it is roadmap/source/maintenance work and must be labeled as such.

## Instructor memory protection
Do not ask the instructor to re-remember a prior ARC decision until repository continuity, source authority, design lineage, prior conversations/files and current code have been searched first.
