## Audit result

The existing Foundation stylesheet owns shell structure and Samsung geometry. A large inline legacy stylesheet follows it and still supplies light prototype colors to most controls and domain surfaces. Equal-specificity rules therefore made a direct rewrite of the Foundation layer risky. The new design system loads after both sources, rebinds legacy semantic variables, and supplies shared component rules without deleting the physically verified geometry.

The representative component map covers:

- shell identity, rail/sidebar, contextual header, active navigation, class menu;
- dashboard identity, current/selected class cards, factual class snapshot;
- cards, student/roster rows, Forecast priorities, pills, tables, forms and tabs;
- student and generic dialogs while retaining the workspace boundary;
- Projects/checkpoints, Project Bank, Teaching Tips, Material Inventory and Booth Manager;
- Settings/update states and explicit Simulation/test-state communication.

## Visual system

The pathway scope is `data-arc-theme="titanium-welding"`, produced by the existing class/program identity boundary. Tokens describe canvas and layered surfaces, steel borders, primary/secondary text, electric-blue interaction, functional success/warning/danger/information, radii, focus, and panel depth. This keeps ARC Core structurally neutral and permits future pathway themes without binding theme selection to one instructor account.

The Dashboard hero is CSS-only. It preserves the Welding/Titanium identity and pathway statement without adding a new workflow or a fabricated lesson/readiness claim. The pilot warning is an expandable, compact operational notice; every prior privacy/offline fact remains in the DOM. Simulation retains its explicit sticky-header banner and obtains only a presentation-state class.
